# Tabella completa

| Algoritmo / Framework | Categoria                    | Input                        | Output                | Pipeline (semplificata)                                          | Vantaggi                                                                         | Svantaggi                                                         | GitHub                                                         |
| --------------------- | ---------------------------- | ---------------------------- | --------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------- |
| **OpenPose**          | 2D Pose Estimation           | 1 immagine RGB               | Keypoint 2D           | CNN → Part Affinity Fields → Skeleton                            | Storico, multi-persona, robusto, supporta corpo, mani e volto.                   | Lento, ormai superato, elevato consumo di VRAM GPU.               | https://github.com/CMU-Perceptual-Computing-Lab/openpose       |
| **AlphaPose**         | 2D Pose Estimation           | 1 immagine / video           | Keypoint 2D           | YOLO → Crop → HRNet → Pose 2D                                    | Molto accurato, realtime, supporta tracking multi-persona e stima della posa 3D. | Produce solo pose 2D, dipende dalla qualità del detector iniziale | https://github.com/MVIG-SJTU/AlphaPose                         |
| **MMPose**            | Framework                    | RGB                          | Pose 2D / 3D / Mesh   | Detector → Modello scelto → Output                               | Decine di modelli, aggiornato, modulare                                          | Non è un algoritmo singolo                                        | https://github.com/open-mmlab/mmpose                           |
| **VoxelPose**         | Multi-view 3D Pose           | Più telecamere RGB calibrate | Pose 3D multi-persona | HRNet → Heatmap → Voxel Grid → Cuboid Proposal → Pose Regression | Molto robusto alle occlusioni, niente triangolazione                             | Richiede più telecamere calibrate e molta GPU                     | https://github.com/microsoft/voxelpose-pytorch                 |
| **PoseFormer**        | 3D Pose Estimation           | Sequenza di pose 2D          | Pose 3D               | Pose 2D → Transformer → Pose 3D                                  | Ottimo sfruttamento temporale                                                    | Richiede pose 2D accurate                                         | https://github.com/zczcwh/PoseFormer                           |
| **MotionBERT**        | 3D Motion Estimation         | Video / Pose 2D              | Pose 3D temporale     | Pose Sequence → Transformer → Pose 3D                            | Ottimo per il motion capture                                                     | Più pesante computazionalmente                                    | https://github.com/Walter0807/MotionBERT                       |
| **ROMP**              | Human Mesh Recovery          | 1 immagine RGB               | Mesh SMPL             | CNN → SMPL Regression → Mesh                                     | Realtime, semplice                                                               | Accuratezza inferiore ai modelli recenti                          | https://github.com/Arthur151/ROMP                              |
| **PARE**              | Human Mesh Recovery          | 1 immagine RGB               | Mesh SMPL             | Backbone → Attention → SMPL                                      | Molto robusto alle occlusioni                                                    | Più lento di ROMP                                                 | https://github.com/mkocabas/PARE                               |
| **HybrIK**            | Human Mesh Recovery          | 1 immagine RGB               | Mesh SMPL             | CNN → IK Regression → SMPL                                       | Molto accurato, inverse kinematics                                               | Richiede modello SMPL                                             | https://github.com/jeffffffli/HybrIK                           |
| **CLIFF**             | Human Mesh Recovery          | 1 immagine RGB               | Mesh SMPL             | Backbone → Camera-aware Features → SMPL                          | Gestisce bene la prospettiva                                                     | Monocamera                                                        | https://github.com/huawei-noah/noah-research/tree/master/CLIFF |
| **VIBE**              | Video Mesh Recovery          | Video RGB                    | Mesh SMPL + Motion    | CNN → Temporal GRU → SMPL                                        | Ottimo sfruttamento temporale                                                    | Non realtime                                                      | https://github.com/mkocabas/VIBE                               |
| **4D-Humans (HMR2)**  | Human Mesh Recovery          | Video / Immagini             | Mesh SMPL             | ViT → HMR2 → Tracking → Mesh                                     | Stato dell'arte, molto accurato                                                  | Richiede GPU potente                                              | https://github.com/shubham-goel/4D-Humans                      |
| **SAM3DBody**         | Human Mesh Recovery          | 1 immagine RGB               | Mesh MHR + Rig        | Detector → DINOv3 → MHR → LBS                                    | Ricostruzione completa con MHR, rig dettagliato                                  | Repository di ricerca, molto pesante                              | https://github.com/facebookresearch/sam-3d-body                |
| **SAM3DBody-cpp**     | Human Mesh Recovery Realtime | Webcam / Video               | Mesh MHR + BVH        | YOLO11 → DINOv3 → MHR → ONNX → LBS                               | Realtime, esportazione BVH, niente runtime Python                                | Implementazione non ufficiale, richiede conversione ONNX          | https://github.com/FORTH-ModelBasedTracker/SAM3DBody-cpp       |
| **MMHuman3D**         | Framework                    | RGB                          | Mesh, Pose 3D         | Framework → Modello scelto                                       | Contiene HMR, HybrIK, PARE, VIBE, CLIFF ecc.                                     | Framework complesso                                               | https://github.com/open-mmlab/mmhuman3d                        |
